## 0. システム概要（Abstract）
本システムは、ナイトワーク業態（キャバクラ等）における店舗管理者と在籍キャストの双方向コミュニケーション・勤怠管理・罰金管理を目的とした Web アプリケーションである。店舗側とキャスト側は別URL（別ドメインまたは別パス）でアクセスし、それぞれ専用コンソールを持つ。キャストは店舗発行の招待コードによって登録し、以降は Google アカウント認証（OAuth 2.0）でログインする。ただしログイン時には毎回、または初回連携時に招待コードの再入力を求め、所属店舗との紐付けを担保する。

## 1. システムアーキテクチャ要件
### 1.1 URL分離設計
- 店舗側コンソール：`https://admin.{domain}.jp/`
- キャスト側コンソール：`https://cast.{domain}.jp/`
- 両者は別サブドメインとして構築し、Cookie / セッションを完全分離すること。
- バックエンドAPIは単一（例：`api.{domain}.jp`）だが、JWT等のトークンに `role: "shop" | "cast"` を必ず含めロール検証を行うこと。

### 1.2 認証フロー
| 対象 | 認証方式 | 備考 |
|------|---------|------|
| 店舗管理者 | Email + Password（または Google OAuth） | 店舗アカウントは管理者が発行 |
| キャスト | 招待コード + Google OAuth 2.0 | 初回登録時にコード検証 → Google連携。再ログイン時にも招待コードの再入力を必須化 |

- 招待コードは店舗側コンソールから発行（1コード=1キャスト、有効期限設定可）
- Google認証成功後、招待コードと Google アカウントを店舗DB上で紐付ける
- 招待コードの再入力タイミングはセッション有効期限切れごと、または任意設定（例：週1回）とする

## 2. 機能要件（Functional Requirements）
### 2.1 キャスト → 店舗 要望・報告書き込み機能
- キャストは店舗宛に自由記述の要望・相談・連絡事項を投稿できる。
- 可視性ルール（極めて重要）：
  - 店舗側：全キャストからの投稿を一覧で閲覧可能
  - 投稿したキャスト本人：自身の投稿内容のみ閲覧可能（過去投稿の履歴確認可）
  - 他のキャスト：他人の投稿は一切閲覧不可（プライバシー保護）

```
CastMessage {
  id: UUID
  cast_id: FK
  shop_id: FK
  content: TEXT
  created_at: DATETIME
  read_by_shop: BOOLEAN
  shop_reply: TEXT (nullable)
}
```
UI要件：
- キャスト側：「店舗への要望」タブ → 投稿フォーム＋自分の過去投稿一覧
- 店舗側：「キャストからの連絡」一覧画面 → キャスト名でフィルタ可能、未読バッジ表示

### 2.2 罰金管理機能（凍結・遅刻等）
- 店舗側から罰金項目と金額を明示的にキャストへ課すことができる。
- 罰金理由のプリセット：遅刻（時間単位で金額変動可）／無断欠勤／アカウント凍結／ドタキャン／その他（自由記述）

```
Penalty {
  id: UUID
  cast_id: FK
  shop_id: FK
  type: ENUM('late', 'absence', 'freeze', 'cancel', 'other')
  amount: INTEGER (円)
  reason: TEXT
  issued_at: DATETIME
  status: ENUM('pending', 'confirmed', 'paid', 'disputed')
}
```
UI要件：
- 店舗側：キャスト詳細ページから「罰金を課す」ボタン → 種別選択・金額入力・理由記入 → 発行
- キャスト側：ログイン時に未確認罰金があればモーダル通知、罰金履歴タブで累計金額を確認可能
- わかりやすさを最優先：色分け（赤系）、金額の大きな表示、発生日時の明示

### 2.3 出勤（シフトイン）報告機能
- キャストは出勤時に「出勤報告」を提出する。
- 店舗側は提出された出勤報告を確認・承認する。
- 店舗側からも代理で出勤登録が可能（本人不在時等）。
- コメント機能：出勤報告に対して店舗・キャスト双方がコメント可能で、誰が誰の出勤を承認・提出したかが明示される。

```
Attendance {
  id: UUID
  cast_id: FK
  shop_id: FK
  scheduled_at: DATETIME
  actual_check_in: DATETIME
  submitted_by: ENUM('cast', 'shop')
  submitted_by_user_id: FK
  status: ENUM('submitted', 'confirmed', 'no_show')
  comments: [Comment]
}
Comment {
  id: UUID
  attendance_id: FK
  author_id: FK
  author_role: ENUM('cast', 'shop')
  content: TEXT
  created_at: DATETIME
}
```
UI要件：
- キャスト側：ワンタップ「出勤報告」ボタン → 店舗側に通知
- 店舗側：本日の出勤予定・出勤済み一覧、コメントスレッド表示
- コメント欄には投稿者名とロールバッジ（店舗/キャスト）を明示

## 3. コンソール改善要件（UX/UI）
### 3.1 店舗側コンソール
- ダッシュボード：本日の出勤者数、未確認要望件数、当月罰金発行総額をカード表示
- キャスト一覧：検索・並び替え（在籍/凍結/新人 等）
- 通知センター：未読要望・未承認出勤報告を集約

### 3.2 キャスト側コンソール
- ホーム：本日のシフト、未確認罰金、店舗からの返信通知
- シンプルな導線：「出勤報告」「店舗に連絡」「罰金確認」の3大ボタンをファーストビューに配置
- モバイルファースト設計

## 4. 非機能要件
| 項目 | 要件 |
|------|------|
| プラットフォーム | Web（PWA対応推奨） |
| 対応ブラウザ | Chrome / Safari 最新2バージョン |
| セキュリティ | HTTPS必須、JWT認証、CSRF対策、キャスト個人情報の暗号化保存 |
| プライバシー | 他キャストの投稿はDB取得時点でクエリレベル遮断（フロント側フィルタは不可） |
| ログ | 罰金発行・出勤承認は監査ログを保持 |

## 5. 技術スタック推奨（外部新設時の参考）
- フロントエンド：Next.js 14 (App Router) / TypeScript / Tailwind CSS / shadcn/ui
- バックエンド：Node.js (Hono / NestJS) または Python (FastAPI)
- DB：PostgreSQL
- 認証：NextAuth.js（Google Provider）+ 招待コード検証ミドルウェア
- ホスティング：Vercel（フロント）+ Supabase / Railway（DB）

> ※ 現行キャバ帳リポジトリでは D-3 に従い React18+Vite+Firebase を採用済み。本節は別スタックで新設する場合の参考。

## 6. 実装優先順位（開発フェーズ）
1. Phase 1（MVP）：認証（招待コード + Google OAuth）、URL分離、キャスト・店舗基本CRUD
2. Phase 2：出勤報告機能＋コメント機能
3. Phase 3：キャスト→店舗の要望書き込み機能（可視性ルール厳守）
4. Phase 4：罰金管理機能
5. Phase 5：コンソールUX改善、通知、ダッシュボード

## 7. AIエージェント向け実装指示（そのまま貼付用）
上記仕様に基づき、Next.js 14 (App Router) + TypeScript + PostgreSQL + NextAuth.js を用いてフルスタックWebアプリを実装してください。

最重要制約：
1. 店舗側 (/admin) とキャスト側 (/cast) はルーティングを完全分離し、middleware.ts でロール検証を行うこと
2. キャスト投稿の可視性は DB クエリ (WHERE cast_id = current_user_id) で制御し、フロントエンドで制御しないこと
3. Google OAuth 認証後も、セッション有効期限が切れた際は招待コード再入力画面へリダイレクトすること
4. 罰金発行UIは赤系カラーで警告的にデザインし、キャスト側では未確認罰金をモーダルで強制表示すること
5. すべてのAPIエンドポイントに監査ログを実装すること

まずは Phase 1（認証とURL分離）から着手し、動作確認できる段階で報告してください。
