# クロードデザイン 全画面プロンプト（デザイン → 実装へ渡す）

今の動くモックと同じ**全16画面**をクロードデザイン（claude.ai の Artifact）で作らせ、
**そのままこのリポジトリのReact実装へ移植できる**形で受け取るためのプロンプト集。

- **PART A**：マスタープロンプト（1回貼れば「俯瞰ギャラリー＋操作モード」の全画面Artifactが出る）
- **PART B**：1画面だけ作り込む/直すときのテンプレ（ヘッダー共通）
- **PART C**：渡し方（デザイン→実装、実装→デザインの往復）

> 実装移植の肝：出力は **React + Tailwind**、色トークンは `night(#1f1147)` / `gold(#c9a24b)`、props は指定の型に一致、ダミーは1箇所の `const data`。これで移植が near-1:1 になる。

---

## PART A：マスタープロンプト（そのままコピペ）

```
あなたはナイトワーク向けアプリ「キャバ帳」のUIデザイナー兼フロントエンド実装者です。
以下の仕様で、全16画面を「俯瞰ギャラリー＋タップで操作できる実動モック」として1つのArtifactに作ってください。
既存の「キャバ帳アプリUIプロンプト集」の規約があれば優先します。

# デザインシステム
- ブランド: 夜×高級感。ダークネイビー #1f1147 / シャンパンゴールド #c9a24b / ソフトローズ #e6789b
- 面: グラスモーフィズムのカード、上品でフェミニン、モダンな日本語UI、余白広め
- 端末: スマホ枠（幅430px想定・ノッチ）。ヘッダーは safe-area 対応（padding-top: max(env(safe-area-inset-top),12px)）
- 下部: 5タブ（ホーム/顧客/予定/返信/メニュー）
- 遷移: iOS風。詳細/フォームは右からスライドイン＋「‹ 戻る」、タブでルート切替、モーダルは下からのボトムシート
- ライト/ダーク両対応、フォーカス可視、reduced-motion 尊重

# 登録・修正フォームの操作性（重要）
- 列挙値はタップ選択（セグメント/ピル）: ランク・支払・相性・消耗度など
- 必須未入力は 赤枠＋シェイク＋エラーメッセージ で保存をブロック（あだ名など）
- 画面下に sticky な保存バー（保存/キャンセル）、トグルスイッチ、来店登録はボトムシート
- 保存で トースト表示＋一覧へ即反映、編集はプリフィル、数値は大きめのタップ領域

# 出力契約（実装へ移植するため厳守）
- React + Tailwind CSS のみ（外部ライブラリは React 以外禁止／アイコンはインラインSVGか絵文字）
- 色は Tailwind の night(=#1f1147) / gold(=#c9a24b) を使用。他は標準Tailwind
- 各画面は表示専用コンポーネントに分割し、props は「データ契約」の型に一致させる（内部でデータ取得しない）
- ダミーデータは1箇所の const data にまとめ、削除しやすくする
- 状態（画面遷移・登録・編集）はローカルstateで動かしてよい（デモ用）。ただしデータ表示はpropsの型に沿う

# データ契約（TypeScript・この型に合わせる／Timestampは {toDate():Date} とみなす）
type Yen=number
type CustomerRank='VVIP'|'VIP'|'IP'|'LOVE'|'BADBOY'   // 1番の太客/定期太客/見込み/スキピ/痛客
type FitLevel='得意'|'普通'|'苦手'; type Fatigue='低'|'中'|'高'
type PaymentMethod='cash'|'card'|'urikake'; type ScheduleType='shift'|'dohan'|'after'|'appointment'
interface Fit{level:FitLevel;reasonTags:string[];fatigue:Fatigue}
interface Bottle{name:string;price:Yen}
interface Customer{id:string;nickname:string;lineName?:string;occupation?:string;companyName?:string;incomeRange?:string;
  paymentMethods:PaymentMethod[];tags:string[];rank?:CustomerRank;fit?:Fit;pinnedCautions:string[];
  totalSpent:Yen;visitCount:number;riskScore:number;riskFlags:string[];memo?:string}
interface Visit{id:string;date:{toDate():Date};amount:Yen;durationMin?:number;bottles:Bottle[];
  isDohan:boolean;isAfter:boolean;payment:PaymentMethod;urikakePaid?:boolean;episodeMemo?:string}
interface Schedule{id:string;type:ScheduleType;customerId?:string;start:number;end:number;memo?:string}
interface ReplySuggestion{tone:'軽め'|'標準'|'丁寧';text:string}

# 全16画面（この順で俯瞰ギャラリーに並べ、タップで操作モードに入る）
1. ログイン … ブランドロゴ＋「はじめる」。タップでホームへ
2. ホーム … 今日の予定 / ⚠️要確認顧客（riskScore>=50）/ クイックタイル（売上・黒服）/ 今日のひとこと連絡（F-07）/ 太客TOP
3. 顧客一覧 … 検索・ランクフィルタ・並び替え（更新/売上/リスク）、行タップで詳細、＋新規
4. 顧客詳細 … プロフィール＋累計/来店/リスクの3指標、リスクアラート（>=50黄/>=70赤＋riskFlags＋赤時セルフチェック）、相性(fit)チップ、気をつけること(pinnedCautions)、来店タイムライン、来店登録/占い/返信案/編集/削除
5. 顧客 新規登録 … 上記フォーム操作性を全面適用。あだ名必須
6. 顧客 編集 … 5と同じフォームでプリフィル＋更新
7. 予定一覧 … 今日/今後、Googleカレンダー連携中バッジ、行タップで編集、＋追加
8. 予定 追加/編集 … 種別ピル（同伴/アフター時のみ顧客選択）、日付・開始/終了、メモ、保存で同期✓トースト
9. 返信アシスト … 顧客選択＋相手メッセージ→3案（軽め/標準/丁寧）をカード表示＋コピー
10. 黒服相談 … 落ち着いた濃紫のチャット。キーワードで #9110/店/窓口 のエスカレーションカードを出し分け
11. 占い・相性診断 … 自分/相手の誕生日＋関係性ピル→相性ランクS〜D＋関係別スコア＋総評＋注意点チェック→顧客に保存
12. 売上レポート … 保証カウントダウン、指名リング、今月売上/同伴、太客TOP5、ランク別構成
13. お知らせ … 店舗からの発信（看板イベント/バースデーノルマ/シフト）
14. メニュー … 売上/黒服/お知らせ/店舗コンソール導線＋ログアウト
15. 店舗コンソール(一覧) … 担当店舗一覧（別サーフェス想定・トーンをやや管理画面寄りに）
16. 店舗コンソール … タブ（発信/メンバー/売上確定/ランキング）。ランキングは公開範囲を選択

まず全画面をスマホ枠サムネイルで俯瞰できるボードを作り、各カードをタップすると
その画面から実際に操作できる（遷移・登録・編集が動く）ようにしてください。
```

## PART B：1画面だけ作り込む/直すテンプレ

PART A の「デザインシステム」「操作性」「出力契約」「データ契約」を先頭に貼り、続けて：

```
# 対象画面
- 画面名: 顧客詳細（リスクアラート付き）
- props: { customer: Customer; visits: Visit[] }
- 仕様: （PART Aの「4. 顧客詳細」の内容）
# サンプルデータ（const data にまとめる）
（src/fixtures/sample.ts の sampleCustomer / sampleVisits を貼る）
# 出力: 表示専用 React コンポーネント CustomerDetail({customer,visits}) を1ファイルで
```

対象画面・props・サンプルだけ差し替えれば全画面ぶん量産できる。型は `src/types`、データは `src/fixtures/sample.ts`。

## PART C：渡し方（往復）

### デザイン → 実装（クロードデザイン → クロードコード）
1. claude.ai でキャバ帳Project の新規チャットに **PART A を貼って送信** → 全画面Artifactが出る
2. 気に入るまでプレビューで確認・口頭修正
3. Artifact の**コードをコピー**（or URLを控える）してクロードコード（このリポジトリ）に貼り
   「これを React 実装へ移植して」と依頼
4. こちらで **ダミー`const data` → `src/fixtures/sample.ts` → Firestore取得** の順に差し替え、`src/pages/…` へ結線

### 実装 → デザイン（型・データを渡す）
- 「この画面の型とサンプルを出して」と言えば、クロードコードが PART B に差し込む
  **型ブロック＋サンプルブロック**をそのまま生成する

### トークンを増やすとき
- 色を足すなら `tailwind.config.js` に追加し、その名前を PART A の「出力契約」にも書く（両環境で同名に）
