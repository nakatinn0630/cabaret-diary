## 0. 本書のスコープと前提

- 本書は **業務要件（何を実現するか）** を定義する。システム設計（アーキテクチャ・技術選定・データ物理設計）はv1.0第2部および別途システム化要件定義に委ねる。
- **未決の前提**：実装プラットフォーム（React PWA / iOSネイティブ）は本書時点で未確定。本書の業務要件はプラットフォーム非依存で記述する。
- 本書で追加する機能ID：**F-12（顧客ランク体系）／F-13（向き不向き登録）／F-14（占い・相性診断）**。既存のF-01〜F-11はv1.0を踏襲する。
- 追加3機能に共通する業務目的：**「誰を、どの熱量で、どう扱うか」の判断をキャスト本人が言語化・記録し、日々の接客とLINE営業の質を安定させること。**

## 1. 追加要件の背景と目的

### 1.1 背景
キャストは顧客ごとに「太客か見込みか」「気が合うか」「今日は何に気をつけるべきか」を**感覚で判断**しており、体調や気分で接客の質がぶれる。また新人・移籍時に顧客の温度感が引き継げず、太客化のチャンスを逃す。占い・相性は水商売の会話フックとして日常的に使われるが、記録・再利用されていない。

### 1.2 目的（追加分）
| # | 目的 | 対応する成果指標（KPI） |
|---|---|---|
| G4 | 顧客を熱量・役割で区分し、営業リソースの配分を最適化する | ランク別の指名転換率・離脱率 |
| G5 | 相性と注意点を可視化し、接客・返信の失敗（地雷）を減らす | 「注意点」参照後の顧客離脱率の低下 |
| G6 | 占いを会話フック兼セルフケアの材料として資産化する | 占い起点の連絡実施率・返信率 |

### 1.3 利用者
一次ユーザーはキャスト本人のみ（v1.0を踏襲）。顧客（データ主体）は本機能に直接触れない。ランク・向き不向き・相性はいずれも**ユーザー本人の主観的評価**であり、他者に共有されない。

## 2. F-12 顧客ランク体系（顧客レベル区分）

### 2.1 目的
顧客を「売上上の役割」と「感情上の役割」で分類し、営業の優先度と接し方を明確化する。既存の`tags`（VIP/新規/要注意/太客）を、排他的な**単一ランク**へ格上げして体系化する。

### 2.2 ランク定義
| コード | 呼称 | 定義（業務上の意味） | 主な営業方針 |
|---|---|---|---|
| **VVIP** | 1番の太客 | 売上最上位。指名・同伴・場内の中心。失うと売上に直撃 | 関係維持を最優先。特別感の演出、記念日対応を手厚く |
| **VIP** | 定期的な太客 | 安定して高額利用する常連。月内に複数回来店 | 来店リズムの維持。飽きさせない話題供給 |
| **IP** | 見込み客 | 太客化が期待できる新規〜育成中。単価/頻度は発展途上 | 接触頻度を上げ、次回来店の確約を取りにいく |
| **LOVE** | スキピ（好きピ） | キャスト自身が個人的に好意を持つ客。売上と切り離れる場合あり | 営業と私情の線引きを意識。感情移入の自己管理 |
| **BADBOY** | 痛客（バッドボーイ） | トラブル・精神的負担・売掛/危険リスクが大きい要注意客 | 距離を保つ。深追いしない。必要に応じ黒服相談 |

### 2.3 業務ルール
- ランクは**1顧客につき1つ**（排他）。ただし補助的な`tags`（新規・誕生日近い 等）は従来通り複数付与可。
- ランクは**手動設定を基本**とし、システムは**推奨ランクを提案**する（確定はユーザー）。
  - 推奨ロジック例：累計売上・来店頻度の上位帯 → VVIP/VIP候補、来店1〜2回かつ単価未確定 → IP候補、リスクスコア70点以上（v1.0 F-02）→ BADBOY候補。
  - LOVE（スキピ）は感情要素のため**自動提案しない**（手動のみ）。
- ランク変更は履歴（いつ・どのランクから）を残す。降格（VVIP→VIP等）はKPI分析の重要シグナル。
- ランクは既存機能に波及する：
  - **F-07 特別連絡レコメンド**：VVIP/VIP/LOVEを優先、BADBOYは非営業連絡の推奨対象から除外。
  - **F-06 返信案生成**：ランクに応じてトーン（VVIP=丁寧×特別感 / IP=距離を詰める / BADBOY=事務的・境界線重視）を切替。
  - **F-09 売上レポート**：ランク別の人数構成・売上構成・転換率（IP→VIP等）を可視化。

## 3. F-13 向き不向き登録（相性メモ）

### 3.1 目的
顧客ごとに「自分と**合う/合わない**」をキャスト本人が自己評価して登録し、接客前に確認できるようにする。占い（F-14）が生年月日ベースの客観指標なのに対し、F-13は**実接客に基づく主観評価**を担う。

### 3.2 機能要件
- 顧客詳細に「向き不向き」セクションを設け、以下を登録する。
  - **相性区分**：`得意`（向いている）／`普通`／`苦手`（向いていない）の3段階（将来5段階拡張可）。
  - **理由タグ（複数選択）**：会話が弾む／聞き役が向く／テンションが合う／下ネタ耐性／説教されがち／束縛が強い／マウント傾向／金払いは良いが疲れる 等（マスタから選択＋自由記述）。
  - **自分の消耗度**：接客後の疲労感を3段階で記録（セルフケア機能と連動）。
- 一覧画面で「得意な客」「苦手な客」でフィルタ可能。出勤前に**苦手客の来店予定があれば注意表示**。
- 向き不向きは**ランク（F-12）と独立**（例：VVIPだが「苦手」＝重要だが気を張る客、という状態を表現できる）。この掛け合わせが接客戦略の要になる。

### 3.3 ランク×向き不向きの接客サマリ
顧客詳細に、ランクと向き不向きを掛け合わせた**一言サマリ**を自動表示する。
| ランク＼相性 | 得意 | 苦手 |
|---|---|---|
| VVIP | 最強の関係。維持最優先で自然体を活かす | 売上の要だが消耗大。事前準備と回復をセットで |
| VIP | 安定株。会話の型を再現し飽きさせない | 距離感を固定化し、無理に踏み込まない |
| IP | 太客化の最有力。接触頻度を上げる | 育成対象だが優先度は下げてよい |
| LOVE | 私情と営業の線引きに注意 | 相性は悪いが情がある。感情管理を最優先 |
| BADBOY | 扱えるが気を抜かない。境界線を維持 | 最も要警戒。深追い禁物・黒服相談を検討 |

## 4. F-14 占い・相性診断

### 4.1 目的
客と自分の占い（生年月日等）から**相性**を診断し、その顧客に対して「**気をつけるべきこと**」を提示・選択・保存できるようにする。会話フック（占いの話題）とセルフガイド（地雷回避）の二役を担う。

### 4.2 入力
- **ユーザー自身の占い基礎情報**（プロフィールに1回登録）：生年月日（必須）、血液型（任意）。
- **顧客の占い基礎情報**：生年月日（任意・分かる範囲）、血液型（任意）。未登録項目は診断から除外する。
- **占い方式の選択（複数可）**：
  | 方式 | 必要入力 | 用途 |
  |---|---|---|
  | 動物占い（個性心理学） | 生年月日 | キャラ理解・会話フック |
  | 星座（西洋占星術） | 生年月日 | 相性・話題 |
  | 干支 | 生年 | 話題・相性の補助 |
  | 血液型 | 血液型 | 会話フック（参考値） |
  | 数秘術（誕生数） | 生年月日 | 性格傾向 |

### 4.3 出力
1. **相性ランク**：`S / A / B / C / D` の5段階（内部スコア0–100から算出）。
2. **相性サマリ**：関係性の傾向を1〜2文で提示（例：「距離を詰めるほど良くなるタイプ同士」）。
3. **気をつけるべきこと（注意点リスト）**：診断結果に応じた注意点候補を**チェックボックスで提示**。ユーザーが**気になる項目を選択（ピン留め）**でき、選んだ項目は顧客詳細に保存され、接客前・返信案生成前に表示される。
   - 注意点候補の例：「押しすぎると引く」「メンツを立てると機嫌が良い」「話を遮らない」「金銭の話は慎重に」「連絡はマメより間を空ける方が刺さる」「否定されると不機嫌になる」等（方式×相性のマスタから生成）。
4. **会話フック**：「占い好き？実は相性めっちゃ良いらしいよ」等、話題化用の一言案（F-06返信案生成に連携）。

### 4.4 ランク×相性の診断（統合ロジック）
「それぞれの相性で診断可能とする」の要件に対応し、**顧客ランク（F-12）を診断結果に必ず反映**する。相性ランクだけでなく、ランクとの組み合わせで注意点と方針を出し分ける。
| 例 | 出力方針 |
|---|---|
| VVIP × 相性S | 「天性の相性。特別感を演出しつつ、慢心せず記念日を確実に押さえる」 |
| VIP × 相性C | 「相性は普通。会話の型（鉄板ネタ）で安定運用。無理に深掘りしない」 |
| IP × 相性A | 「太客化の最大チャンス。占いを口実に接触頻度を上げる」 |
| LOVE × 相性S | 「のめり込み注意。私情と売上を切り分け、依存し過ぎない」 |
| BADBOY × 相性D | 「地雷確率最大。深追い禁止・境界線を明確に・黒服相談を推奨」 |

### 4.5 業務・倫理ルール（重要）
- 占い結果は**エンタメ・会話補助・自己整理の材料**であり、**顧客の人格や行動を断定するものではない**旨をUIに明示する。
- 相性が悪い・BADBOY判定でも、**顧客を貶める表現や差別的断定は生成しない**（黒服機能の応答方針に準拠）。
- 危険・トラブルの兆候（v1.0 F-02リスクスコア高、ストーカー等）は占いで代替せず、**必ず黒服機能・警察相談導線（#9110）へ誘導**する。占いはリスク判断の代替にしない。
- 占い基礎情報（生年月日等）は顧客の個人情報。v1.0のセキュリティ要件（本人以外アクセス不可・保存時暗号化）に従う。

## 5. データモデル追加（業務レベル）

v1.0の `users/{uid}/customers/{cid}` を拡張する（物理設計は別途）。

```
customers/{cid}
  rank: enum(VVIP|VIP|IP|LOVE|BADBOY)      // F-12 単一ランク（任意・未設定可）
  rankHistory: [{ rank, changedAt, note }]  // ランク変更履歴
  fit: {                                    // F-13 向き不向き
    level: enum(得意|普通|苦手)
    reasonTags: string[]                    // 理由タグ（複数）
    fatigue: enum(低|中|高)                  // 接客後の消耗度
    note: string
  }
  fortune: {                               // F-14 占い基礎情報
    birthday?: date
    bloodType?: enum(A|B|O|AB)
  }

customers/{cid}/compatibility/{diagId}      // F-14 診断結果（履歴）
  methods: string[]                         // 使用した占い方式
  rankResult: string                        // S|A|B|C|D
  summary: string
  cautionCandidates: string[]               // 提示された注意点候補
  pinnedCautions: string[]                  // ユーザーが選択・保存した注意点
  createdAt: timestamp

users/{uid}/profile
  fortuneBase: { birthday: date, bloodType?: enum }  // 自分の占い基礎情報
```

## 7. 既存機能への影響一覧

| 既存機能 | 影響 |
|---|---|
| F-02 リスクアラート | リスクスコア70点以上をBADBOY推奨の入力に。ただし占いはリスク判断を代替しない |
