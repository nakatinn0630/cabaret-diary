# コワーク引き継ぎ — 残タスク プロンプト集

キャバ帳（Cabaret Diary）の残タスクを、コワーク（Claude）にそのまま貼り付けて依頼できる形でまとめたもの。
1タスク＝1プロンプト。上から優先度順。**各プロンプトの先頭に必ず「共通コンテキスト」を付けて渡すこと。**

---

## 共通コンテキスト（毎回プロンプトの先頭に貼る）

```
リポジトリ: nakatinn0630/cabaret-diary（React 18 + Vite + TypeScript strict + Tailwind + Firebase）
本番: https://cabaret-diary.web.app （Firebaseプロジェクト: cabaret-diary）/ デモ: /demo

必ず守ること（変更禁止の設計判断）:
- AI黒服「クロ」は警察への通報判断をしない。危険時は担当・店舗など人間へ誘導する。
- 黒服相談と占い結果は端末ローカル(localStorage)のみに保存。Firestoreに保存しない。
- localStorageキーの接頭辞 kyabacho_ は既存ユーザーデータに紐づくため変更しない。
- .env* は絶対にコミットしない（.env.example のみ可）。秘密鍵・APIキーをコードに書かない。
- Firestoreルールの「本人(uid)以外アクセス不可」の境界を緩めない。
- 作業は typecheck と build が通ることを確認してからコミットすること。
参考ドキュメント: docs/キャバ帳_業務要件定義_v1.2.md, docs/キャバ帳_DB設計_v1.0.md, docs/UIレビュー_100件.md
```

## 1. コード分割で初回表示を軽くする 🟡

```
単一バンドルが約800KBあり初回表示が重い。React.lazy + Suspense でルート単位のコード分割を導入して。
- 対象: src/App.tsx のルート（特に console/（店舗）、Compatibility（占い）、Consult（AI黒服）は利用頻度が低く分割効果が大きい）
- Suspense フォールバックはブランド色（night/#1f1147, gold/#c9a24b）の軽いスピナー
- vite build 後に主要チャンクが 300KB 未満になることを確認
- PWA(precache) のエントリ数が増えるのは問題ない
```

## 運用メモ

- デプロイ: `npm run build && firebase deploy --only hosting --project cabaret-diary`（要 `firebase login` か SA認証）
- Firestoreルール変更時: `firebase deploy --only firestore:rules --project cabaret-diary`
- 本番の動作確認はデモ(/demo)でログイン不要で行える（データはローカルのみ、書き込みはDBに行かない）
